01 — THE RESEARCH

A model you can
interrogate.

Every result should be traceable to a dataset, a training run, and a method. Chakaso is built to make that chain inspectable.

01 / MODEL
c.PARAMETERS → PREDICTIONS

Built from scratch

Decoder-only language-model architectures, a tokenizer trained in-project, and a Python-first interface designed for inspecting the actual model artifact.

02 / DATA
SOURCE → DIGEST

Provenance by design

Versioned corpus manifests, content fingerprints, documented licences, and recoverable snapshots help keep experiments reproducible.

Read data cards ↗
03 / EVALUATION
METHOD BEFORE METRIC

Results with context

Experiments report baselines, seeds, budgets, failure modes, and what the numbers cannot establish. Lower loss is not the same as useful language.

Inspect experiments ↗
02 — THE CURRENT REALITY

Progress without
pretending.

Chakaso has a working training and evaluation pipeline, with measured experiments on small models. The current checkpoints do not generate useful, coherent assistant responses. That is a research gap to close, not a detail to hide.

Read the model card ↗
03 — HOW WE WORK

Evidence over
impression.

Research is more useful when other people can verify it, reproduce it, and disagree with it.
